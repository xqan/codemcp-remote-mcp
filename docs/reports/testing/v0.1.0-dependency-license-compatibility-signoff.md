## Review result

The exact RC dependency inventory and bundled third-party notices were reviewed for license compatibility and attribution obligations.

No dependency was identified that blocks distribution of the RC under the project's AGPL-3.0-only license, provided the existing third-party license texts/notices remain bundled and the corresponding project source remains available as required by AGPL-3.0.

### Permissive licenses

MIT, MIT-0, BSD-2-Clause, BSD-3-Clause, ISC, PSF-family, Apache-2.0, and permissive dual-license dependencies do not introduce an identified incompatibility with the project distribution model. Existing license texts and notices must remain intact.

### MPL-2.0

`certifi` is identified as MPL-2.0. MPL 2.0 explicitly defines GNU AGPL 3.0 as a Secondary License and provides a Larger Work mechanism, subject to the MPL conditions and absence of an `Incompatible With Secondary Licenses` designation. The bundled dependency is distributed unmodified and its license evidence is preserved.

Official reference:
https://www.mozilla.org/en-US/MPL/2.0/

### PyInstaller

PyInstaller 6.22.2 is used as the build/bundling tool. Its GPL licensing carries the upstream bootloader exception permitting generated executable bundles to be distributed under the application's chosen license, subject to dependency licenses. The verified upstream `COPYING.txt` is preserved in the release evidence.

Official reference:
https://pyinstaller.org/en/v6.22.2/license.html

### codemcp 0.3.0 metadata discrepancy

The audit found a real upstream metadata discrepancy:

- PyPI/distribution metadata License field: `MIT`
- bundled audited `License-File`: Apache License 2.0
- installed license SHA-256: `cfc7749b96f63bd31c3c42b5c471bf756814053e847c10f3eb003417bc523d30`

The upstream `ezyang/codemcp` repository currently identifies the project as Apache-2.0, while PyPI 0.3.0 metadata reports MIT. This discrepancy is preserved rather than normalized away in `THIRD_PARTY_NOTICES.txt`.

For this RC, the discrepancy is **not a compatibility blocker** because both MIT and Apache-2.0 are permissive licenses compatible with the intended AGPLv3 distribution model. The release must continue to ship the bundled license text and record both facts.

References:
- https://pypi.org/project/codemcp/0.3.0/
- https://github.com/ezyang/codemcp
